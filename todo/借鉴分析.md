# 类似项目借鉴分析

基于 `todo/refs/` 资料 + codegraph 对 sentinel 现状的调查（`analyze_text` 审查流程、
`tools::jev` 改写闭环、规则配置结构），按「可直接借鉴」到「远期」排序。

## 一、规则层补漏（低风险，立即可做）

参照：`humanizer/`（26 模式）、`wikipedia-signs-of-ai-writing/`、`llmstrip/`

sentinel `review.yaml` 已有：解释腔、不是A而是B、把字句、比喻模板、程度推进、重复句首（`collect_sentence_starts`）、章末收束。对照 26 模式可补：

| 缺失模式 | 示例（中文） | 实现方式 |
|---|---|---|
| 三连排比（forced triad） | 「不是勇气，不是智慧，不是运气」 | 新增 regex：`(?:不是\|没有\|因为\|为了)[^，。]{1,12}[，、][^，。]{1,12}[，、]` 检测并列三连 |
| 无对象反驳 | 「这不是X的问题」「我并不是说X」 | 新增 regex：`这不是[^。]{1,20}的问题\|我并不是说` |
| 堆叠限定词 | 「可能也许大概」「似乎好像」 | 新增 modifier 词对检测 |
| 单行戏剧化收尾 | 「这，就是命。」 | 已有 ending 检测，可加戏剧化碎片正则 |

llmstrip 的核心借鉴：**规则清单双用**——review.yaml 既是检测器，也作为改写 prompt 注入生成模型。当前 `rewrite_sentence` 的 system prompt 只有通用约束，可以改成把命中的规则 `note`/`label` 注入，让改写更有针对性。

## 二、改写闭环增强（中风险，直接对应 issue #4 剩余）

参照：`wawawriter/`、`humanizer/`

1. **反向红线复检**：改写后草稿重新跑 `audit-draft`，对比 `warn_sections`/`hard_flags` 数量是否下降。实现：`jev-review --output-draft` 后自动调用 `audit::draft::run`（crate 内可直接调用），在报告中输出「改写前/后规则告警数」。
2. **22 类特征分类 → jev_classify catalog**：把 sentinel 规则类别（解释腔/模板对照/比喻模板/操作日志/流水账/情绪直说/正常）作为 `jev_classify` 的 classes，对命中句做诊断分类——当前 jev-review 只输出 noul 概率，可加 `--classify` 输出类型标签。
3. **voice matching**（humanizer）：用户给 2-3 段参考文本 → sentinel 已有 `corpus_profile`/语料画像（句长/标点/高频词）→ 注入改写 prompt，让改写贴合用户文风。实现：`jev-review --style-sample <file>`，读取样本的语料画像并注入 system prompt。

## 三、风格化生成前置（issue #5 的现成架构）

参照：`sillytavern/`、`rpg-os/`、`ai-dungeon/`、`azgaar-fantasy-map/`

1. **设定卡（Character Card v2/v3 思路）**：设定卡用结构化 JSON（人物/世界/规则/关系），生成时注入。sentinel `audit-concept` 已有概念卡字段规范（缺失字段/分类漂移），可直接复用为设定卡 schema。
2. **动态注入（World Info/Lorebook 思路）**：设定条目 = {关键词, 内容}，按当前场景关键词或 `jev_find` 选择相关条目注入，避免全文设定塞爆上下文。
3. **状态文件持久化（RPG-OS）**：DND 文字冒险的世界/角色/资源状态存成可读文件，确定性代码管规则（骰子/HP/技能），LLM 只管叙述。这是防幻觉破坏游戏性的关键架构。

## 四、评估层（远期可选）

参照：`prometheus-eval/`

jev 是商业端点（本仓库通过兼容端点调用）。prometheus-eval 提供开源 LLM-as-judge（Prometheus-2），可本地部署替代 jev 做改写校验/评分，但需要自建模型服务，收益需评估。

## 建议优先级

1. **P0（本周可做）**：改写 prompt 注入命中规则 note（规则清单双用）+ 反向红线复检（改写后跑 audit-draft 对比告警数）。
2. **P1（issue #4 收尾）**：`--classify` 诊断分类 + voice matching。
3. **P2（issue #5 启动）**：设定卡 schema + 动态注入 + 状态文件架构，基于 SillyTavern/RPG-OS 设计。
